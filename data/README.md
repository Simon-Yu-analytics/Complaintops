# Data policy and schema

The default project run uses deterministic synthetic data generated by
`scripts/generate_sample.py`. The generator produces 6,165 complaints over 52
weeks with product-specific trend, seasonality, and demand shocks. Narratives
include deliberately overlapping language so the routing task is not perfectly
separable.

`data/sample/complaints.csv` is regenerated locally and excluded from Git. A
fresh clone can reproduce it with `make sample`; the generator uses a fixed seed
and does not contact an external service.

## Field dictionary

| Field | Type | Used for |
|---|---|---|
| `complaint_id` | string | uniqueness and traceability checks |
| `date_received` | ISO date | chronological splits and weekly demand |
| `product` | category | routing target and operational queue |
| `issue` | category | issue-mix summaries |
| `narrative` | text | routing model input |
| `state` | two-letter code | schema realism; not used by the model |
| `submitted_via` | category | schema realism; not used by the model |
| `timely_response` | category | retained for future service analysis |

The loader rejects missing columns, blank required values, invalid dates, and
duplicate complaint IDs before analysis. The synthetic generator also prevents
exactly duplicated narrative rows so repeated template combinations cannot cross
the chronological evaluation boundaries unchanged.

## Public-data extension

The schema mirrors selected fields from the public CFPB Consumer Complaint
Database. `complaintops.data.download_cfpb_sample` can retrieve a bounded extract
of at most 10,000 records in a networked environment. It is not called by the
offline pipeline or automated tests.

Real extracts belong in `data/raw/`, which is intentionally excluded from Git.
Before using them, review the CFPB data-use notice and treat free-text narratives
as potentially sensitive. Public complaint counts also require an exposure
denominator before making comparisons between firms.
